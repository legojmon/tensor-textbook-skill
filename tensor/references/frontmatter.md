# 책의 앞부분 (CH 시작 전까지)

한완수 앞부분(커리큘럼 → 로드맵 → 수기 → 소개 → 서문 → Part 표지 → Part 전체 차례 → Part 가이드라인 → Method I)을 그대로 따른다.
`scripts/frontmatter.py` 가 **한 번에 전부** 만든다. 쪽마다 한두 줄만 있는 앞부분은 실패다. 아래 기준을 채운다.

```bash
python <skill>/scripts/frontmatter.py --authors <repo>/author/authors.json --book work/book.json --into work/book.html
```

- 저자 정보: 레포의 **`author/authors.json`**(TENSOR 저자 최재원·김준형, 사진·일러스트·공통 서문 포함)을 기본으로 쓴다. 다른 저자로 만들 때만 `assets/authors/authors.example.json` 양식으로 새로 받는다.
- 책 정보: `assets/authors/book.example.json` 을 `work/book.json` 으로 복사해 과목에 맞게 채운다.
- 기본 문안: `assets/frontmatter.default.json`. book.json·authors.json 에 같은 항목이 있으면 그쪽이 우선한다. 기본 문안은 책에 실제로 있는 장치만 설명하므로 그대로 써도 된다.
- 괄호로 시작하는 값("(소속)")은 빈 칸으로 보고 넣지 않는다. 빈 칸이 남았으면 전달할 때 무엇이 비었는지 알린다.

## 쪽 순서와 분량 기준

| 순서 | 쪽 | 분량 기준 | 데이터 |
|---|---|---|---|
| 1 | TENSOR 커리큘럼 | 학습 단계 4개(강의 → Part1 → Part2 → 실전)를 상자 흐름으로, 지금 책의 Part를 검정으로 강조. 아래 시리즈 표 | `curriculum`(기본 문안), `authors.series` |
| 2 | 학기 로드맵 | 구불구불한 길 위 정류장 5~7개(MID·FINAL 강조) + "언제/무엇을" 표 3~4줄 | `book.semester`, `book.roadmap_steps` (없으면 기본) |
| 3 | 독자 수기 | 동의(`consent: true`)한 실제 후기만. 없으면 쪽 생략 | `book.testimonials` |
| 4 | 소개 ‘TENSOR에 대하여’ | 번호 붙은 항목 **7~10개**, 각 항목 = 굵은 제목 한 줄 + 설명 3~4문장. 한 쪽을 채운다 | 기본 7개 + `book.about`(과목 고유 항목 2~3개 권장) |
| 5 | 서문 | 4~6문단, 한 쪽 분량. 끝에 "- 저자 ○○ · ○○ -" | `book.preface` → 없으면 `authors.preface`(TENSOR 공통 서문) |
| 6 | 저자 소개 | 사진(흑백)·일러스트·약력·저자의 글·막혔던 장면·한마디 | `authors[]` |
| 7 | 이 책의 구성 | 장 흐름(Preview → … → 빠른 정답) + 부분별 역할 6개 + 흑백 범례 8개 | 기본 문안 |
| 8 | Part 표지 | 장 표지와 같은 아치 틀, "PART 2", 제목, 아래 설명 3줄 | `book.part` |
| 9 | Part 전체 차례 | 한완수식 3단(장 이름 / Preview·TOPIC·문제·Review / 쪽). 가이드라인 묶음 포함. **쪽 번호 자동** | 자동(paginate.js) |
| 10 | Part 가이드라인 | 1. 어떤 학생이 공부해야 하는가?(CHECK 자가진단 O/X 4개+) 2. Part 목표(Part1 ①~④ → Part2 ①~③) 3. 메인은 ‘원서 개념’이다(인용 두 줄) 4. 소통. **2쪽 이상** | 기본 문안 + `part.checklist`, `part.goals`, `authors.contact` |
| 11 | Method I 시험 개념에 대한 이해 | 1. ‘왜’: 원고 첫 TOPIC의 EX + 원서적 해법 + 시험 개념 박스 + 시험적 해법 + 해설 2. ‘어떻게’: 4문단 3. 메인은 원서 개념: 둘째 EX + 비교표(특징 ①~④, 목표) + 맺음. **3~4쪽** | EX는 원고에서 자동 추출 |

Part1 책이면 가이드라인 목표가 Part1용으로 바뀌고 Method I 는 넣지 않는다.

## 머리 모양 (글꼴 통일)
- 한 쪽짜리 앞부분(커리큘럼·로드맵·소개·서문·저자 소개·이 책의 구성)은 큰 제목(Pretendard 800) + 아래 선.
- 가이드라인은 **본문 TOPIC 쪽과 같은 머리**(위 띠 `Part2 가이드라인` + 큰 제목 `Part2 가이드라인` + 선)를 쓴다. Method I 는 선 아래 `✎ Method I | 시험 개념에 대한 이해` 막대로 시작한다.
- 앞부분 글꼴은 본문과 같다. 제목·표·상자 = Pretendard, 글 = Noto Serif KR. 다른 글꼴이나 이미지 글자를 쓰지 않는다.

## Method I 의 EX
- `frontmatter.py` 가 원고의 `article.manuscript > section.topic` 중 번호가 있는 TOPIC에서 **원서적 해법이 붙은 첫 EX** 를 찾아 [EX, 원서적 해법, 시험 개념 박스, 시험적 해법]을 그대로 가져온다. EX 출처 칸에 `[본문 TOPIC 01]` 이 붙는다.
- 그래서 **첫 TOPIC의 EX 01은 네 부품을 모두 갖춰야** 한다(writing-style.md 의 TOPIC 틀). 하나라도 없으면 Method 1절은 설명 글로 대신하고 실행 결과에 경고가 나온다.
- 셋째 절의 EX 02 는 둘째 TOPIC의 첫 EX(없으면 첫 TOPIC의 둘째 EX)를 쓴다.
- 앞부분은 원고를 다 쓴 **뒤에** 넣는다. 원고를 고친 뒤에는 같은 명령을 다시 돌린다(기존 앞부분을 교체한다).

## 저자에게 받을 것
`author/README.md` 의 표가 기준이다. 비어 있는 항목은 그 표를 보여 주고 요청한다.
1. 이름·영문 이름·소속, 소개하고 싶은 경험 2~3가지(사실만)
2. 이 과목에서 실제로 막혔던 한 장면(문제, 처음 시도, 나중에 알아본 단서)
3. 독자에게 해 줄 말 1~2문장, 이 책에서 특히 신경 쓴 부분과 이유
4. 증명사진(정면, 밝은 단색 배경, 4:5), 일러스트(선택), 서명(선택)
5. 소통 창구(정오 제보 메일, 질문 창구)
6. 책마다: 학기 일정, 과목에서 꼭 전하고 싶은 것 2~3개(→ 소개 항목 추가), 서문을 과목에 맞게 쓸지 여부

## 글 다듬기 규칙
- 서문만 저자 1인칭("우리는")을 허용한다. 나머지는 `writing-style.md` 대로 평서문.
- 저자의 경력·성과·수치·일화를 새로 지어내지 않는다. 받은 메모만 다듬는다. 수기를 지어내지 않는다.
- 소개 항목과 가이드라인은 **책에 실제로 있는 장치**만 말한다(없는 QR·Q&A 게시판 등을 쓰지 않는다).
- 광고 문구 금지(`writing-style.md` §7): "최고의", "완벽한", "~만 보면 된다" 같은 약속을 하지 않는다.
- TENSOR 저자(최재원·김준형)의 사진·연락처는 본인들이 공개를 정해 `author/` 에 있다. 그 밖의 사람의 사진·학번·연락처는 공개 레포에 올리지 않고 첨부로만 받는다.

## 확인
- 렌더 후 앞부분 쪽을 PNG로 열어 본다. 한 쪽에 내용이 절반도 안 차는 쪽이 있으면 해당 항목(소개 항목, 로드맵 단계, 서문)을 보강한다.
- Part 전체 차례의 쪽 번호가 실제 쪽과 맞는지 PDF에서 두 군데 이상 대조한다.
- `lint.py` 경고 0개(범례 견본은 검사에서 빠진다).
