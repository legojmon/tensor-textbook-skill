# Tensor 문체·작성 가이드 (반드시 이대로 쓴다)

이 문서는 **말투, 문장, 문단, 부품별 작성 틀, 분량, 금지 표현**을 정한다. 과목과 상관없이 똑같이 적용한다.
품질 기준 원고는 `example-manuscript.html` 이다. 쓰기 전에 그 원고의 TOPIC 01을 처음부터 끝까지 읽고, 쓴 뒤에 나란히 놓고 비교한다.

---

## 0. 한 문장 요약
> **선배가 옆에서 문제를 같이 보며, "왜 이렇게 생각해야 하는지"를 평서문으로 차분하게 짚어 주는 글.**
> 정답만 주는 해설집도, 감탄하는 블로그도, 딱딱한 논문도 아니다.

---

## 1. 말투

### 1-1. 문장 끝 (본문·해법·박스 공통)
| 쓰임 | 쓰는 끝 | 예 |
|---|---|---|
| 사실·정의·결론 | **~이다 / ~한다 / ~된다** | "극은 회로가 정한다." |
| 함께 하자는 제안 | **~해 보자 / ~확인해 두자** | "다음 문제를 보자." "원서 개념으로 확인해 두자." |
| 독자가 해야 할 일 | **~해야 한다 / ~를 의심해야 한다** | "문제를 읽는 순간 다음 의문을 가져야 한다." |
| 논리 연결 | **즉, ~ / 따라서 ~ / 그런데 ~ / 다시 말해 ~** | "즉 답은 처음부터 지수 안에 있었다." |
| 관찰을 짚기 | **~에 주목하자 / 여기서 놓치기 쉬운 점이 있다** | |

- **존댓말(~합니다)은 Preview·Review·표지·소개 문구에서만** 쓴다. 본문(TOPIC)·해법·개념 박스·TIP·채점 포인트는 전부 평서문(~이다).
- 한 문단 안에서 말투를 섞지 않는다.
- 독자를 부르는 말("여러분", "학생 여러분")은 Preview·Review에서만, 본문에서는 쓰지 않는다.

### 1-2. 톤
- 확신 있게 말한다. "~인 것 같다", "~일 수도 있다", "아마" 금지. 조건이 있으면 조건을 명시한다("극이 모두 좌반면일 때만 최종값 정리를 쓴다").
- 감탄·과장 금지: "놀랍게도", "엄청", "매우 중요한", "꿀팁", "치트키", "!!" 
- 학생의 실패를 비난하지 않는다. 대신 **왜 그렇게 하게 되는지**를 설명한다("14장을 배운 직후라 손이 먼저 s영역 회로를 그리려 한다").
- 말풍선(§4-6) 한 곳에서만 구어체를 허용한다.

### 1-3. 용어
- 원서 용어는 **한국어 표준 용어 + 처음 한 번 영문 병기**: "최종값 정리(Final Value Theorem)". 두 번째부터 한국어만.
- 교재 고유 용어는 정확히 이 표기만 쓴다: **원서 개념, 원서 간접 개념, 시험 개념, 원서적 해법, 시험적 해법, 강의 선정 문제, 적용문제, 연습문제, 채점 포인트, CORE, TIP**.
- 본문에서 이 용어를 처음 언급할 때는 태그로 쓴다: `<span class="tg ws">원서 개념</span>`, `<span class="tg">시험 개념</span>`. 같은 문단에서 반복할 때는 일반 글자.
- 강의자·교수님 실명은 쓰지 않는다. "강의", "강의록"으로 쓴다.

---

## 2. 문장

- **한 문장 = 한 정보.** 60자를 넘으면 나눈다. "~하고, ~하며, ~해서"를 세 번 이상 잇지 않는다.
- 주어를 생략하지 않는다(특히 "이것이", "그것은" 대신 실제 대상을 쓴다: "이 계수에는", "극은").
- 숫자·식은 문장 안에 넣되 긴 식은 별행 수식(`$$…$$`)으로 뺀다. 별행 수식 앞 문장은 "~하면", "~이고", "다음과 같다."로 끝낸다.
- 단위: 숫자와 단위 사이 한 칸, 수식 안에서는 `\ \text{V}`. 결과값에는 **반드시 단위**.
- 강조(`<b>`)는 **문단당 최대 2곳**, 그 문단의 결론 구절에만. 문장 전체를 굵게 하지 않는다.
- 괄호 남발 금지. 부연은 한 문장 안에 괄호 1개까지.

---

## 3. 문단

- 문단 = **3~4문장**, 주장 하나. 5문장을 넘으면 나눈다.
- 문단의 첫 문장이 그 문단의 결론이거나 질문이다. 근거는 뒤에.
- 문단과 문단은 접속어로 잇는다: **그런데 / 즉 / 따라서 / 이때 / 정리하면 / 반대로**.
- 다음 부품(EX, 말풍선, 해법 박스)으로 넘어가는 문단은 **넘어가는 문장으로 끝낸다**:
  - "다음 문제를 보자."
  - "문제를 읽는 순간 다음 의문을 가져야 한다."
  - "이 의문에서 출발하면 ~를 거꾸로 읽어 낼 수 있다."
  - "EX 02에서 다시 연습해 보자. 이번에는 미지수가 세 개다."
  - 이런 연결 문단에는 `class="keep-next"` 를 붙여 다음 부품과 같은 쪽에 놓이게 한다.

## 4. 부품별 작성 틀

각 부품은 **아래 틀의 순서와 분량을 지킨다.** `{ }` 는 채우는 자리.

### 4-1. TOPIC 제목
- 8~16자, **행동형 또는 판단형**. 명사 나열 금지.
- 좋음: "응답식에서 회로 읽기", "분모는 전원을 끄고 본다", "최종값 정리를 믿기 전에", "입력이 바뀌면 곱하는 것만 바뀐다"
- 나쁨: "라플라스 변환의 응용", "전달함수", "부분분수 전개 방법"

### 4-2. 소절 제목 (`<h3>`)
- "1. {핵심을 담은 짧은 구}" — 예: "1. 응답식의 세 숫자", "2. 숫자를 세라"
- TOPIC당 2~3개.

### 4-3. 도입 문단 (TOPIC 첫 문단, 2개)
```
[문단 1] {이 장에서 배운 정방향 절차/개념}을 한 줄로 상기한다. (흐름 칩·그림이 있으면 여기)
[문단 2] 그런데 시험에서는 {이 TOPIC이 다루는 상황}이 반복해서 나온다.
         {강의 예제 번호들}과 {원서 문제 번호들}이 모두 이 구조다.      ← 근거 번호 필수
         원서 본문은 이것을 따로 정리해 주지 않는다. 다음 문제를 보자.
```
- 근거 번호는 실제 INVENTORY에서 확인한 번호만 쓴다. 3~7개.

### 4-4. EX
- 지문은 **원서 문제의 의미를 유지한 한국어 재작성**. 번역투 금지("~가 주어졌을 때 ~를 결정하라" → "~일 때, ~를 구하시오").
- 문제 지문만 **"~하시오/~구하시오"** 로 끝낸다.
- 주어진 식은 별행 수식으로. 조건은 문장 순서대로: 회로/상황 → 시점 조건 → 주어진 값 → 묻는 것.
- 출처: `[원서 Example 14.7-1<br>강의 p.12]` 형식.

### 4-5. 원서적 해법 (회색 박스)
- 단계 번호 ①②③… 각 단계 첫머리에 **굵게 상황 이름**: "**$t<0$** :", "**최종값 12** :"
- 원서 방식 그대로, 계산을 건너뛰지 않는다. 한 단계에 식 1~2개.
- 마지막 단계에 `∴ 결과 = 값 단위`.

### 4-6. 관찰 문단 → 말풍선 → 연결
```
[관찰 문단, 3~4문장]
풀이에 틀린 곳은 없다. 그런데 {결과}를 결정한 것은 {실제로 쓰인 정보} 하나뿐이었다.
{나머지 정보}는 {어디}를 거쳐 다시 나왔을 뿐 새로운 정보를 주지 않았다.
(다시 말해 ~.)

[연결 문단, keep-next]
핵심은 {문제의 특징}이라는 점이다. 문제를 읽는 순간 다음 의문을 가져야 한다.

[말풍선] 학생 속마음 한 문장, 구어체, 25자 안팎, "…" 또는 "?"로 끝.
   좋음: "응답식을 다 줬는데… 이걸 또 s영역으로 풀어야 해?"
         "지수와 로그가 같이 나왔네? 설마 역함수 관계 아냐?"
   나쁨: "이 문제는 응답식 해부를 이용하면 쉽게 풀 수 있다." (설명문 금지)

[연결 문장] 이 의문에서 출발하면 {무엇}을 거꾸로 읽어 낼 수 있다.
```

### 4-7. 시험적 해법 (보라 박스)
- 첫 줄: 무엇을 대응시키는지 한 문장 + 필요하면 `\underbrace` 로 구조를 보여 주는 식.
- 단계는 **원서적 해법보다 확실히 짧게**(보통 3단계 이하). 검산 단계는 "(검산)"으로 표시하고 ✓.
- 그림이 도움이 되면 강조색 그림(전원을 끈 회로 등).
- 박스 뒤 한 줄: "{생략된 것}도 없다. {N} 줄이면 끝난다." 같은 대비 문장 **1개만**.

### 4-8. 원서 개념으로 논증
```
그렇다면 이것이 왜 성립하는지 [원서 개념]으로 확인해 두자. {원서적 해법의 중간 결과}에서
· {원서 정리 1} : {식} → {결론}
· {원서 정리 2} : {식} → {결론}
· {핵심 관찰} : {이유}.ⓐ
정리하면 {한 문장 결론, 굵게}. {이 TOPIC 유형에서 할 일} 뿐이다.
```
- 원서 정리 이름 + 절 번호를 쓴다("최종값 정리(원서 14.5절)").
- 본문에 다 못 쓰는 증명은 ⓐⓑ 각주 + 해설로.

### 4-9. 시험 개념 박스
- 제목: 4~10자 명사구("1차 응답식 해부", "독립 정보 세기").
- 내용: 조건 한 줄 → **표**(숫자/의미/구하는 법) 또는 **번호 절차 ①②③** → 결론 한 줄.
- 박스 안에 서술 문단을 2개 이상 넣지 않는다. 표·절차 위주.

### 4-10. CORE
- 정확히 이 형식 한 줄: `[{조건/상황}] ⟹ [{바로 할 행동}]`
- 50자 안팎. 예: "[응답식이 주어진 역추적 문제] ⟹ [상수 = 최종값, t=0 값 = 초기값, 지수 = 1/τ 를 먼저 쓰고 미지수와 맞춘다]"

### 4-11. 저자의 특강 TIP
- 제목 6~12자, 태도나 습관에 관한 것("끝까지 풀지 않는 용기", "생각의 기준", "그래프를 먼저 그리는 이유").
- 본문 1문단 4~5문장: **흔한 습관 → 그 습관의 비용 → 반대 극단의 위험 → 구체적 행동 지시**.
- 챕터당 2~3개. 공부법 일반론(계획표, 회독수) 금지.

### 4-12. 답안·채점 포인트
- 첫 문단 1~2문장: 이 유형이 어떻게 채점되는지. 강의록에 채점 기준이 있으면 그 기준을 근거로("소문항마다 배점, 단위 틀리면 감점").
- 이어서 **번호 목록 4~6줄**: 답안에 쓸 줄을 순서대로. 각 줄 = "{무엇} → {결과} ({형식})".
- 마지막 줄은 이 유형에서 가장 많이 감점되는 실수 방지("단위까지", "해가 유일하지 않음을 명시").

### 4-13. 강의 VS 연습문제 표
- 행 4~6개. 왼쪽: 실제 번호(강의 Ex·원서 P). 오른쪽: "{변형 요소, 굵게} → {대처}".
- 표 뒤 1~2문장: 시험 변형 예상 + "기준만 잡혀 있으면 출발점은 같다" 류의 마무리.

### 4-14. Preview (존댓말)
- 3문단 + 〈학습 방법〉 ①~⑤.
  1. 이 장이 무엇을 하는 장인지 + Part1과 Part2의 차이 (2~3문장)
  2. 이 장 문제들에서 눈에 띄는 **구조 하나**와 왜 첫 TOPIC으로 삼았는지 (3~4문장)
  3. 나머지 TOPIC 나열 (1~2문장)

### 4-15. Review: 개념진단 (존댓말)
- OVERVIEW 2문단: TOPIC들이 어떻게 이어지는지 / 다음 장과의 연결.
- O/X: TOPIC마다 체크 문항 3~5개, 모두 **"~를 설명할 수 있는가? / ~를 아는가?"** 로 끝.

### 4-16. 문제 지문 (L·A·B)
- §4-4와 같은 규칙. 그림 참조는 "그림의 회로에서", "그림 (a)", "그림 (b)".
- 객관식이 아니면 선지를 만들지 않는다.

## 6. 금지 목록

- 원서 문장을 번역해 이어 붙이기, 원서 그림 잘라 붙이기
- "~인 것 같다", "아마", "놀랍게도", "꿀팁", "치트키", 이모지, "!!"
- 본문에서 존댓말·"여러분"
- 근거 번호 없는 "시험에 자주 나온다"
- 유도 없는 공식 암기 권유("이 공식을 외우자")
- 공부법 일반론 페이지(사용자가 요청한 경우 제외)
- 교수님 실명, 특정 학교 시험 원문 그대로 인용
- 검증하지 않은 답

## 7. 쓰고 나서 자가 점검 (TOPIC마다)

1. 문단마다 첫 문장만 이어 읽어도 TOPIC의 논리가 통하는가?
2. 원서적 해법 → 관찰 → 말풍선 → 시험적 해법 → 논증 → 박스 → CORE 순서가 지켜졌는가?
3. 본문에 존댓말이 섞이지 않았는가? 말풍선만 구어체인가?
4. 결과값마다 단위가 있는가? 모든 답을 sympy로 확인했는가?
5. `example-manuscript.html` 의 TOPIC 01과 나란히 놓았을 때 밀도·길이가 비슷한가?
