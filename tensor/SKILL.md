# Tensor — 강의록 + 원서 PDF → 시험 특화 교재 + 표지

**입력은 강의록 PDF와 원서 PDF.** 원서가 둘이면 둘 다, 강의 랩·실습 페이지(HTML·PDF), 시험 복기가 있으면 함께 받는다. 과목은 상관없다(회로이론, 신호및시스템, 미적분학, 일반물리, 유기화학, 경제원론, 자료구조 …).
출력: 내지 A4 PDF + 앞표지·뒷표지·책등·인쇄용 펼침면 PDF.

**형식은 쓰는 사람이 정하지 않는다.** 원고는 `work/book.json` 에 글만 쓰고, `scripts/build.py` 가 표지·목차·Preview·워밍업 문제(준비 칸)·TOPIC 부품(EX, 원서적·시험적 해법, 말풍선, 3탭 개념 박스, CORE, TIP, 채점 포인트, 강의 VS 연습문제 표)·적용문제·연습문제·실전 문제·Review·빠른 정답·해설을 고정 HTML/CSS 로 조립한다. HTML·CSS 를 직접 쓰는 경로는 없다. 필수 부품이 빠지면 빌드가 실패하므로 **누가 만들어도 같은 모양**이 나오고, 내용 품질은 아래 문서로 맞춘다.

## 반드시 읽을 것 (작업 시작 전에 전부)
1. `references/content-rules.md` — 개념 3분류, 시험 개념 추출, 문제 출처, 해법 두 층, 채점 포인트, 검증
2. `references/writing-style.md` — **말투·문장·문단·부품별 작성 틀·분량·금지 표현** (이대로 쓴다)
3. `references/manuscript-schema.md` — **JSON 원고 형식.** 블록 종류, 필수 순서, 분량 규칙, 빌더 오류의 뜻
4. `references/example-manuscript.json` — **완성 원고 견본.** 밀도·순서·말투를 이것에 맞춘다 (조판 결과는 `examples/demo/demo.pdf`)
5. `references/book-format.md` — 책 구조, 쪽 순서, 그림 규격, 흑백 인쇄 규칙
6. `references/cover-design.md` — 표지·책등 규칙
7. 책 전체를 만들 때 `references/frontmatter.md` — CH 앞의 11개 쪽(커리큘럼~Method I) 구성과 분량 기준

## 0단계. 환경 준비
```bash
python <skill>/scripts/setup.py        # 최초 1회, 현재 Python 환경에 설치
python <skill>/scripts/selfcheck.py    # 견본 JSON → HTML → PDF 를 만들어 기준 쪽과 대조
```
`<skill>` 은 이 SKILL.md 가 있는 폴더다. selfcheck 가 통과해야 빌더·렌더러가 정상이다.

## 1단계. 입력 분석 (자동)
```bash
python <skill>/scripts/extract.py --lecture 강의록.pdf --textbook 원서.pdf [--solutions 해설집.pdf] --out work/
```
- `work/INVENTORY.md` 를 읽는다: 원서 장 범위, 절 목록, 예제·연습·장 끝 문제, 강의 ↔ 원서 대응표.
- `work/lecture/sheet_*.png` 를 **전부** 본다. 수식·그림은 텍스트 추출이 깨진다. 대응표에 빠진 강의 예제는 수치·그림을 원서와 비교해 직접 짝짓는다.
- 원서·강의록이 스캔본이면(INVENTORY에 ⚠ 표시) 쪽 이미지를 보고 목록을 직접 만든다.
- 강의록이 원서를 쓰지 않는 과목(자체 노트)이면 강의록을 "원서"로 보고 진행하되 1-B에서 알린다.
- 강의 랩·실습 페이지가 있으면 텍스트로 뽑아(`work/lab/*.txt`) 측정 수치, 흔한 구현 실수, 슬라이드 정정 사항, 연습 문제를 목록으로 만든다. 본문의 "강의 랩 노트" 박스(`concept` kind `ind`)와 실전 문제(X)의 재료가 된다.
- **불일치 목록**을 만든다: 강의 슬라이드 그림과 강의 코드가 다른 곳(예: BST 삭제가 그림은 후임자, 코드는 전임자), 원서와 강의의 규약 차이(높이를 0부터/1부터), 원서 부록 정답의 오류. 본문에 어느 규칙을 따랐는지 적고, 정답 오류는 해설에 "원서 정답 정정"으로 남긴다.
- 보조 교재가 있으면(예: Goodrich 주교재 + Lafore 보조) 책마다 장 번호 체계가 다르다. 어느 책의 몇 장인지 INVENTORY 에 따로 적고, 원고의 `sources` 에 책마다 이름과 장 번호를 선언한다.

## 1-B단계. 제작 전 확인 질문 — **생략 금지**
분석이 끝나면 **만들기 전에 반드시** 사용자에게 묻는다. 질문 도구(Claude의 AskUserQuestion / Codex의 request_user_input / 채팅)가 있으면 그것으로, 각 질문에 **자유 입력 칸**을 남긴다. 사용자가 이미 말한 항목은 "이렇게 이해했다"로 확인만 한다. **답을 받기 전에는 원고를 쓰지 않는다.**

**항상 확인** (분석 결과를 보여주며)
1. 과목명(정식 명칭)과 장: "강의록은 ○장 ○○, 원서 『제목』 ○판 p.○–○로 찾았습니다. 맞나요?"
2. 범위: **Part1+Part2 한 권(기본)** / Part2만 / Part1만 / TOPIC 1개 시안. 사용자가 따로 말하지 않으면 한 권에 Part1(원서 개념의 정리)과 Part2(시험 개념의 완성)를 모두 담는다
3. 시험 형식: 서술형·객관식·혼합, 오픈북·계산기 여부 → 채점 포인트 방향을 정한다
4. 추가 자료: 해설집, 채점 기준이 있는 풀이, 과거 시험 — 있으면 첨부 요청
5. 문제 쪽 배치: 쪽당 2문제(기본, 풀이 공간 넉넉) / 쪽당 4문제(짧은 계산 문제)
6. 그림 방식: **다시 그리기(기본, 흑백에 최적)** / 원서 그림 그대로 쓰기(개인 인쇄용, 흑백 변환) / 섞기
   + 출력: 흑백(인쇄)만 / 흑백 + 컬러(화면용) 두 벌(`build.py --color`)

**표지를 만들 때 확인**
7. 교재명(기본 TENSOR), 부제(기본 "시험 개념의 완성"), 저자 표기
8. 학교 로고: 서울대면 내장 흰색 로고(`"logo": "snu"`), 다른 학교면 투명 배경 PNG/SVG 첨부 요청
9. 표지색·책등색(기본 #6B3FD4), 글꼴 조합(serif·sans·classic), 예상 쪽수 또는 제본집이 알려준 책등 두께

**자료 문제 — `INVENTORY.md` 의 "⚠ 확인 필요" 항목을 전부 사용자에게 보여주고 처리 방법을 묻는다**

| 발견된 문제 | 사용자에게 보여줄 내용 | 선택지 (+ 자유 입력) |
|---|---|---|
| **강의록 일부 없음** (쪽 수가 너무 적음, 강의에 나온 절이 원서 장에 없음, 강의가 다른 장 내용을 참조) | 빠진 것으로 보이는 절·예제 번호 | 나머지 강의록 첨부 / 있는 강의록 범위까지만 / 원서 기준으로 채움 |
| **원서 없음 / 장을 못 찾음 / 판이 다름** | 찾은 범위, 못 찾은 강의 예제 번호 | 원서 첨부 / 쪽 범위 직접 지정 / 강의록만으로 진행(원서 개념=강의 개념) |
| **해설집 없음** | 답이 없는 장 끝 문제 수 | 해설집 첨부 / 원서 Answer 있는 문제만 사용 / 직접 풀어 sympy 검증 후 사용 |
| **강의 예제를 원서에서 못 찾음** | 번호·강의 쪽 목록 | 강의 자체 예제로 표기 / 원서 대응 직접 알려줌 |
| **스캔본·흐린 그림** | 해당 쪽 | 더 나은 파일 첨부 / 보이는 범위에서 다시 그림 |
| **과목에 맞는 그림 도구 없음** (구조식 등) | 필요한 그림 종류 | 단순화한 SVG / 그림 없이 서술 / 사용자가 그림 제공 |
| **보조 교재의 장 번호가 주교재와 다름** | 책별 장·절 대응 | 주교재 번호로 통일 / 책 이름을 붙여 병기 |

- 항목이 하나도 없어도 "자료 점검 결과 문제 없음"을 한 줄로 알리고 "항상 확인" 1~6을 묻는다.
- 사용자가 "알아서 해"라고 하면 표의 첫 번째가 아닌 **가장 안전한 선택**(검증 가능한 문제만 사용 등)으로 진행하고, 무엇을 골랐는지 전달 때 적는다.
- **질문을 보낸 턴은 거기서 끝낸다.** 같은 턴에 원고·그림을 만들지 않는다.
- 답을 받으면 **사용자의 말을 그대로** 원고의 `approval.answers` 에 옮긴다: `materials`(자료 점검·누락 자료 처리), `scope`(범위), `exam`(시험 형식), `layout`(문제 쪽 배치·출력), `figures`(그림 방식). 사용자가 맡긴 항목은 그 말과 고른 기본값을 함께 적는다(`"알아서 해 → 쪽당 2문제, 흑백"`). 답을 지어 넣지 않는다. 다섯 칸 중 하나라도 비었거나 `{{…}}`·`미정` 같은 자리표시면 `build.py` 가 빌드하지 않는다.

## 2단계. TOPIC 설계 → **사용자 확인 (생략 금지)**
- `content-rules.md` §3: 장 끝 문제를 훑어 문제마다 "결정적 관찰"을 적고, 2개 이상 반복되는 것을 **시험 개념**으로 묶는다.
- TOPIC 6~12개. 첫 TOPIC은 강의 예제가 가장 많이 걸린 시험 개념. 시안 1개만 만들 때도 전체 목록을 짜고, 만들 1개를 표시한다.
- **아래 형식 그대로** 보여주고 확인받는다. 확인 전에는 원고를 쓰지 않는다.

```
## TOPIC 구성안 — {과목} {장}장 {장 제목}

| # | TOPIC 제목 | 시험 개념 (한 줄) | 근거: 강의 예제 / 원서 문제 | EX 예정 | 예상 쪽 |
|---|---|---|---|---|---|
| 01 | 응답식에서 회로 읽기 | 상수=최종값, 지수=1/τ 로 소자 역추적 | 강의 Ex 14.7-1·14.7-2·14.8-3 / P14.7-1·2·6·7, P14.8-1 | Ex 14.7-1, 14.7-2, 14.8-3 | 5 |
| 02 | … | … | … | … | … |

- 원서 본문에만 있고 시험 개념으로 묶이지 않은 내용: {목록} → Part1에서 다룸
- 반복이 1회뿐이라 TOPIC에서 뺀 후보: {목록}
- 워밍업(W): {번호 목록} / 적용문제(A) 후보: {번호} / 연습문제(B) 후보: {번호} / 실전 문제(X): {유형}
```
Part1+Part2 한 권(기본)이면 **Part1 구성안도 같은 턴에 함께** 보여 준다. Part1 TOPIC은 원서 절 순서를 따르고, 강의에서 다룬 절 + 장 끝의 '답 확인과 설계 예제'(How Can We Check·DESIGN 절)로 짠다.

```
## Part1 TOPIC 구성안 — {과목} {장}장 {장 제목}

| # | TOPIC 제목 | 원서 절 | 원서 개념(박스) | EX 예정(원서 예제·강의 예제) | 확인문제(Exercise) |
|---|---|---|---|---|---|
| 01 | 정의와 기본 변환쌍 | 14.2 | 정의식, 변환표, 성질표 | Example 14.2-1·14.2-3·14.2-4 | P14.2-1 |

- 뺀 절: {MATLAB·PSpice 등 도구 절}
```
질문(선택지 + 자유 입력): "이대로 진행 / TOPIC 추가·삭제·병합 / 순서 변경 / 특정 TOPIC만 먼저(시안)".
- 사용자가 수정하면 고친 표를 다시 보여주고 한 번 더 확인받는다. 확정된 표가 원고의 `plan` 이 된다.
- 승인한 사용자의 말을 `approval.plan_ok` 에, 승인한 표의 TOPIC 을 `"01 제목"` 목록으로 `approval.plan` 에 그대로 적는다. 나중에 `plan` 을 바꾸면 `approval.plan` 과 달라져 빌드가 멈춘다. 그때는 바뀐 표를 다시 보여 주고 승인받는다.

## 3단계. 문제 고르기
- **워밍업 문제(W)**: 강의에서 푼 원서 예제·문제 중 각 TOPIC의 EX 01이 해부할 것. 출처 `원서 Example 14.7-1 · 강의 p.12`. 문제마다 `pre`(준비 칸)에 정의·규칙 한두 줄(답은 쓰지 않는다)과 `hint` 한 줄을 넣어 처음 보는 사람도 풀 수 있게 한다.
- **EX**: TOPIC마다 2~3개. **적용문제(A)**: 원서 Exercise/Practice + 같은 구조의 장 끝 문제, TOPIC마다 1개 이상. **연습문제(B)**: 장 끝 문제 중 TOPIC을 고르게 덮는 것, 4개 이상.
- **실전 문제(X)**: 장마다 5개. 1-B의 시험 형식을 그대로 따른다(예: T/F 5문항에 이유 한 줄 → 중간 상태 손추적 → 강의 코드 변형 손코딩). 강의 랩의 함정과 시험 복기 유형을 넣는다. 출처 `실전 · 근거`.
- 원서가 둘이면 연습문제를 두 원서에서 고르게 뽑고, `sources` 에 선언한 이름으로 출처를 쓴다(`보조 R-9.13`).
- 문제 번호는 W·A·B·X 네 가지뿐이다(빌더가 순서대로 붙인다). 다른 글자를 만들지 않는다. 모든 답은 `answers` 에 넣어 장 끝 **빠른 정답·해설**(W → A → B → X)이 되게 한다.
- 각 문제의 답을 원서 Answer·해설집과 대조할 수 있게 번호를 기록한다. 답이 없는 문제는 싣지 않는다.

## 4단계. 그림 — 원서·강의록 그림을 빠짐없이 쓴다
- `work/figures/figures.md` 에 원서 그림이 캡션·쪽·관련 예제/문제 번호와 함께 자동으로 잘려 있다(흑백 200dpi). ⚠ 표시는 자동 자르기가 의심스러운 것 → `textbook/p*.png` 를 보고 `figtools.py crop` 으로 다시 자른다.
- 강의록 그림(예제 회로, 그래프, 강의 판서)은 `lecture/p*.png` 를 보고 `figtools.py crop 강의록.pdf <쪽> --box …` 로 잘라 둔다.

- 1-B 답에 따라:
  - **다시 그리기(기본)**:
    - 회로: `scripts/circuits.py` (builder + schemdraw). 흑백 기본이라 강조 소자는 굵은 검정선
    - 그래프·블록도·좌표·자료구조 그림: matplotlib 또는 손으로 쓴 SVG
    - 그린 뒤 **반드시** `figtools.py compare 원본.png 다시그린.svg -o work/compare/x.png` 로 대조 시트를 만들고 열어, 소자 값·라벨·방향·연결·스위치 동작을 하나씩 확인한다
  - **원본 그대로**: `figtools.py mono` 로 흑백·대비 보정 후 사용. 캡션·쪽번호가 같이 잘리지 않았는지 확인
- 강의록에만 있는 그림(교수님이 직접 그린 도식, 판서)은 출처에 강의 쪽 번호를 남긴다.

## 5단계. 원고 쓰기 — `work/book.json`
- `references/manuscript-schema.md` 의 형식으로 **JSON 에 글만 쓴다.** 견본은 `references/example-manuscript.json`.
- 승인받은 구성안을 `plan` 에 그대로 옮기고, 1-B 답을 `scope`·`per_page`·`theme`·`sources` 에 반영한다.
- TOPIC 하나는 이 순서다(빌더가 검사): 소절 제목 → 도입 문단(근거 번호) → EX 01 → 원서적 해법 → 관찰 문단 → 연결 문단 → 말풍선 → 시험적 해법(적용 조건) → 원서 개념으로 논증 → 시험 개념 박스(적용 조건) → CORE → (TIP) → EX 02… → 채점 포인트 → 강의 VS 연습문제 표.
- **문체는 `writing-style.md` 를 그대로 따른다.** 각 부품은 그 문서의 작성 틀을 쓴다. 분량도 그 문서의 숫자다(빌더가 EX 2~3개, 채점 4~6줄, VS 4~6행, Preview 3문단, Review 2문단, ox 3~5개를 확인한다).
- Preview·Review 문단과 모든 W·EX·A·B·X 의 `answers` 까지 한 JSON 에 쓴다. 빠지면 빌드되지 않는다.
- 강의 랩 자료가 있으면 관련 TOPIC의 첫 CORE 뒤에 "강의 랩 노트" 박스(`concept`, kind `ind`)를 넣는다.
- 빌드:
```bash
python <skill>/scripts/build.py work/book.json          # → work/book.html (오류 0개까지 JSON 을 고친다)
python <skill>/scripts/build.py work/book.json -o work/book_color.html --color   # 컬러판을 함께 줄 때
```
- 빌더 오류는 `[오류] TOPIC 03 블록 12: 시험적 해법에 적용 조건(cond) 없음` 처럼 위치를 가리킨다. `book.html` 을 손으로 고치지 않는다. 고치면 lint 가 잡는다.
- **분량 하한**: TOPIC 하나의 본문은 한글 1,500자 이상이어야 빌드된다(수식·태그 제외, 견본 TOPIC 01 은 약 2,300자). 첫 EX 의 원서적 해법은 3단계 이상. 짧다는 오류가 나면 부품을 늘리지 말고 도입·관찰·논증 문단과 EX 02·03 을 견본 밀도로 쓴다.
- `--lenient` 는 사용자가 분량 규칙 완화를 명시적으로 허락했을 때만 쓴다. 그 말을 `approval.lenient` 에 적어야 빌더가 받아 주고, 전달 때 그 사실을 적는다.
- 여러 장을 한 책으로 낼 때는 장마다 JSON 을 따로 쓰고 한 번에 빌드한다: `build.py work/ch08.json work/ch09.json … -o work/book.html`. HTML 을 이어 붙이지 않는다.
- **Part1+Part2 한 권(기본)**: 장마다 Part1 원고 `work/ch08_p1.json`(`"part": "Part1"`, 형식은 `manuscript-schema.md` §4 Part1)과 Part2 원고 `work/ch08.json` 을 쓰고 `build.py work/ch08_p1.json work/ch09_p1.json work/ch08.json work/ch09.json -o work/book.html` 처럼 Part1 장들을 먼저 넘긴다. 사용자가 장별로 받기를 원하면 장마다 Part1·Part2를 따로 빌드해 중간본으로 보내고, 마지막에 한 권으로 빌드한다. `work/front.json` 에 `"index": true` 를 넣어 개념 박스 인덱스를 붙인다.
- `build.py` 는 결과에 **도장**(내용 해시)을 찍는다. `render.py` 는 도장이 없거나 내용과 다르면(손으로 쓰거나 고친 HTML) 조판하지 않고, `lint.py` 도 경고한다. 고칠 것은 언제나 JSON 이다.

### 5-B. 앞부분 (CH 시작 전까지: 책 전체를 만들 때는 반드시)
- 원고를 다 쓰고 `build.py` 로 `work/book.html` 을 만든 뒤 `references/frontmatter.md` 를 읽고 그대로 만든다. 한완수처럼 **커리큘럼 → 학기 로드맵 → (수기) → 소개 → 서문 → 저자 소개 → 이 책의 구성 → Part 표지 → Part 전체 차례 → Part 가이드라인 → Method I** 순서이다. 앞부분 원고는 `assets/authors/book.example.json` 을 복사한 `work/front.json` 에 쓴다(TOPIC 원고 `work/book.json` 과 다른 파일).
```bash
python <skill>/scripts/frontmatter.py --authors <repo>/author/authors.json --book work/front.json --into work/book.html
```
- 저자 정보는 레포 `author/authors.json`(최재원·김준형)을 기본으로 쓴다. 비어 있는 칸(괄호로 시작)은 `author/README.md` 표와 `assets/authors/author-workbook.md` 의 시작 질문 세 개를 보여 주고 요청한다. 저자의 경험·인용은 직접 받은 내용만 쓴다. 편집자가 제안한 서문은 초안으로 표시한다.
- Method I 는 첫 TOPIC 의 EX 01(원서적 해법 + 시험 개념 박스 + 시험적 해법)을 자동으로 인용한다. 그래서 첫 TOPIC 의 EX 01 은 네 부품을 모두 갖춘다(빌더가 검사한다).
- `build.py` 를 다시 돌리면 `book.html` 이 새로 만들어지므로 그 뒤에 `frontmatter.py` 를 다시 실행한다. 렌더 후 앞부분 쪽을 PNG로 열어 반쪽도 안 찬 쪽이 없는지, Part 전체 차례의 쪽 번호가 맞는지 확인한다.

## 렌더링이 안 될 때
브라우저 엔진을 못 찾으면 `book.html` + `fig/` 를 그대로 주고 "Chrome에서 열기 → 인쇄 → A4, 여백 없음, 배경 그래픽 켜기 → PDF로 저장"을 안내한다. 쪽 나눔은 브라우저 안에서 똑같이 된다. 이때도 `book.html` 은 build.py 가 만든 것이어야 한다.
