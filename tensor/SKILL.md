# Tensor — 강의록 + 원서 PDF → 시험 특화 교재 + 표지

**입력은 강의록 PDF와 원서 PDF 두 개.** 과목은 상관없다(회로이론, 신호및시스템, 미적분학, 일반물리, 유기화학, 경제원론 …).
출력: 내지 A4 PDF + 앞표지·뒷표지·책등·인쇄용 펼침면 PDF. 형식은 이 스킬의 CSS·템플릿·쪽 나눔 엔진이 고정하므로 **누가 만들어도 같은 모양**이고, 내용 품질은 아래 문서들을 지켜서 맞춘다.

## 반드시 읽을 것 (작업 시작 전에 전부)
1. `references/content-rules.md` — 개념 3분류, 시험 개념 추출, 문제 출처, 해법 두 층, 채점 포인트, 검증
2. `references/writing-style.md` — **말투·문장·문단·부품별 작성 틀·분량·금지 표현** (이대로 쓴다)
3. `references/book-format.md` — 책 구조, 페이지 순서, HTML 부품, 자동 쪽 나눔·문제 쪽 배치
4. `references/example-manuscript.html` — **완성 원고 견본.** 밀도·순서·말투를 이것에 맞춘다
5. `references/cover-design.md` — 표지·책등 규칙

---

## 0단계. 환경 준비
```bash
bash <skill>/scripts/setup.sh          # KaTeX, Pretendard, schemdraw, sympy, playwright
```
`<skill>` 은 이 SKILL.md 가 있는 폴더다.

## 1단계. 입력 분석 (자동)
```bash
python3 <skill>/scripts/extract.py --lecture 강의록.pdf --textbook 원서.pdf [--solutions 해설집.pdf] --out work/
```
- `work/INVENTORY.md` 를 읽는다: 원서 장 범위, 절 목록, 예제·연습·장 끝 문제, 강의 ↔ 원서 대응표.
- `work/lecture/sheet_*.png` 를 **전부** 본다. 수식·그림은 텍스트 추출이 깨진다. 대응표에 빠진 강의 예제는 수치·그림을 원서와 비교해 직접 짝짓는다.
- 원서·강의록이 스캔본이면(INVENTORY에 ⚠ 표시) 쪽 이미지를 보고 목록을 직접 만든다.
- 강의록이 원서를 쓰지 않는 과목(자체 노트)이면 강의록을 "원서"로 보고 진행하되 1-B에서 알린다.

## 1-B단계. 제작 전 확인 질문 — **생략 금지**
분석이 끝나면 **만들기 전에 반드시** 사용자에게 묻는다. 질문 도구(AskUserQuestion / 선택지 입력)가 있으면 그것으로, 각 질문에 **자유 입력 칸**을 남긴다. 사용자가 이미 말한 항목은 "이렇게 이해했다"로 확인만 한다.

**항상 확인** (분석 결과를 보여주며)
1. 과목명(정식 명칭)과 장: "강의록은 ○장 ○○, 원서 『제목』 ○판 p.○–○로 찾았습니다. 맞나요?"
2. 범위: 장 전체 / TOPIC 1개 시안 / Part1(원서 개념 정리)도 포함
3. 시험 형식: 서술형·객관식·혼합, 오픈북·계산기 여부 → 채점 포인트 방향을 정한다
4. 추가 자료: 해설집, 채점 기준이 있는 풀이, 과거 시험 — 있으면 첨부 요청
5. 문제 쪽 배치: 쪽당 2문제(기본, 풀이 공간 넉넉) / 쪽당 4문제(짧은 계산 문제)

6. 그림 방식: **다시 그리기(기본, 흑백에 최적)** / 원서 그림 그대로 쓰기(개인 인쇄용, 흑백 변환) / 섞기

**표지를 만들 때 확인**
7. 교재명(기본 TENSOR), 부제(기본 "시험 개념의 완성"), 저자 표기
8. 학교 로고: 서울대면 내장 흰색 로고(`"logo": "snu"`), 다른 학교면 투명 배경 PNG/SVG 첨부 요청
9. 표지색·책등색(기본 #6B3FD4), 예상 쪽수 또는 제본집이 알려준 책등 두께

**자료 문제 — `INVENTORY.md` 의 "⚠ 확인 필요" 항목을 전부 사용자에게 보여주고 처리 방법을 묻는다**

| 발견된 문제 | 사용자에게 보여줄 내용 | 선택지 (+ 자유 입력) |
|---|---|---|
| **강의록 일부 없음** (쪽 수가 너무 적음, 강의에 나온 절이 원서 장에 없음, 강의가 다른 장 내용을 참조) | 빠진 것으로 보이는 절·예제 번호 | 나머지 강의록 첨부 / 있는 강의록 범위까지만 / 원서 기준으로 채움 |
| **원서 없음 / 장을 못 찾음 / 판이 다름** | 찾은 범위, 못 찾은 강의 예제 번호 | 원서 첨부 / 쪽 범위 직접 지정 / 강의록만으로 진행(원서 개념=강의 개념) |
| **해설집 없음** | 답이 없는 장 끝 문제 수 | 해설집 첨부 / 원서 Answer 있는 문제만 사용 / 직접 풀어 sympy 검증 후 사용 |
| **강의 예제를 원서에서 못 찾음** | 번호·강의 쪽 목록 | 강의 자체 예제로 표기 / 원서 대응 직접 알려줌 |
| **스캔본·흐린 그림** | 해당 쪽 | 더 나은 파일 첨부 / 보이는 범위에서 다시 그림 |
| **과목에 맞는 그림 도구 없음** (구조식 등) | 필요한 그림 종류 | 단순화한 SVG / 그림 없이 서술 / 사용자가 그림 제공 |

- 항목이 하나도 없어도 "자료 점검 결과 문제 없음"을 한 줄로 알리고 "항상 확인" 1~5를 묻는다.
- 답을 받기 전에는 원고를 쓰지 않는다. 사용자가 "알아서 해"라고 하면 표의 첫 번째가 아닌 **가장 안전한 선택**(검증 가능한 문제만 사용 등)으로 진행하고, 무엇을 골랐는지 전달 때 적는다.

## 2단계. TOPIC 설계 → **사용자 확인 (생략 금지)**
- `content-rules.md` §3: 장 끝 문제를 훑어 문제마다 "결정적 관찰"을 적고, 2개 이상 반복되는 것을 **시험 개념**으로 묶는다.
- TOPIC 6~12개. 첫 TOPIC은 강의 예제가 가장 많이 걸린 시험 개념. 시안 1개만 만들 때도 전체 목록을 짜고, 만들 1개를 표시한다.
- **아래 형식 그대로** 보여주고 확인받는다. 확인 전에는 원고를 쓰지 않는다.

```
## TOPIC 구성안 — {과목} {장}장 {장 제목}

| # | TOPIC 제목 | 시험 개념 (한 줄) | 근거: 강의 예제 / 원서 문제 | EX 예정 | 예상 쪽 |
|---|---|---|---|---|---|
| 01 | 응답식에서 회로 읽기 | 상수=최종값, 지수=1/τ 로 소자 역추적 | 강의 Ex 14.7-1·14.7-2·14.8-3 / P14.7-1·2·6·7, P14.8-1 | Ex 14.7-1, 14.7-2, 14.8-3 | 5 |
| 02 | … | … | … | … | … |

- 원서 본문에만 있고 시험 개념으로 묶이지 않은 내용: {목록} → Part1에서 다룸
- 반복이 1회뿐이라 TOPIC에서 뺀 후보: {목록}
- 강의 선정 문제(L): {번호 목록} / 적용문제(A) 후보: {번호} / 연습문제(B) 후보: {번호}
```
질문(선택지 + 자유 입력): "이대로 진행 / TOPIC 추가·삭제·병합 / 순서 변경 / 특정 TOPIC만 먼저(시안)".
- 사용자가 수정하면 고친 표를 다시 보여주고 한 번 더 확인받는다.

## 3단계. 문제 고르기
- **강의 선정 문제(L)**: 강의에서 푼 원서 예제·문제. 출처 `원서 Example 14.7-1 · 강의 p.12`
- **EX**: TOPIC마다 2~3개. **적용문제(A)**: 원서 Exercise/Practice + 같은 구조의 장 끝 문제. **연습문제(B)**: 장 끝 문제 중 TOPIC을 고르게 덮는 것.
- 각 문제의 답을 원서 Answer·해설집과 대조할 수 있게 번호를 기록한다.

## 4단계. 그림 — 원서·강의록 그림을 빠짐없이 쓴다
- `work/figures/figures.md` 에 원서 그림이 캡션·쪽·관련 예제/문제 번호와 함께 자동으로 잘려 있다(흑백 200dpi). ⚠ 표시는 자동 자르기가 의심스러운 것 → `textbook/p*.png` 를 보고 `figtools.py crop` 으로 다시 자른다.
- 강의록 그림(예제 회로, 그래프, 강의 판서)은 `lecture/p*.png` 를 보고 `figtools.py crop 강의록.pdf <쪽> --box …` 로 잘라 둔다.
- **본문 EX·문제에 쓰는 그림은 하나도 빠짐없이** 위 원본과 짝지어 둔다(문제 번호 ↔ 그림 파일).
- 1-B 답에 따라:
  - **다시 그리기(기본)**:
    - 회로: `scripts/circuits.py` (builder + schemdraw). 흑백 기본이라 강조 소자는 굵은 검정선
    - 그래프·블록도·좌표 그림: matplotlib 또는 손으로 쓴 SVG
    - 그린 뒤 **반드시** `figtools.py compare 원본.png 다시그린.svg -o work/compare/x.png` 로 대조 시트를 만들어 열고, 소자 값·라벨·방향·연결·스위치 동작을 하나씩 확인한다
  - **원본 그대로**: `figtools.py mono` 로 흑백·대비 보정 후 사용. 캡션·쪽번호가 같이 잘리지 않았는지 확인
- 강의록에만 있는 그림(교수님이 직접 그린 도식, 판서)은 강의 쪽 번호를 그림 아래 작게 남긴다.

## 5단계. 원고 쓰기
- `assets/template.html` → `work/book.html`. 고정 쪽(표지·목차·Preview·Review)은 `<section class="page">`, TOPIC 본문은 `<article class="manuscript">` 안에 블록을 순서대로, 문제는 `<section class="problems" data-per="2">` 안에 `.qitem` 을 순서대로 쓴다. 쪽 나눔·번호·탭·꼬리말·목차 쪽번호·문제 머리는 `paginate.js` 가 만든다.
- **문체는 `writing-style.md` 를 그대로 따른다.** 각 부품은 그 문서의 작성 틀을 쓴다.

## 6단계. 검증
- 모든 답을 **sympy(또는 해당 과목에 맞는 계산)** 로 확인하고 원서 Answer·해설집과 대조. 다르면 원인을 찾기 전까지 싣지 않는다.
- 문체·구조·번호·수식 자동 점검 (경고 0개까지):
```bash
python3 <skill>/scripts/lint.py work/book.html --inventory work/INVENTORY.md
```

## 7단계. 렌더링·검수
```bash
python3 <skill>/scripts/render.py work/book.html --png work/preview/
```
- `[넘침]` 0개, `[브라우저]` 오류 0개.
- 미리보기 PNG를 **전부** 열어 아래 체크리스트로 검수 → 고치고 다시 렌더링.

## 8단계. 표지·책등
```bash
cp <skill>/assets/cover/cover.example.json work/cover.json   # 1-B 답으로 채운다
python3 <skill>/scripts/cover.py work/cover.json -o work/cover/
```
- `back_paras` 는 지어내지 말고 내지 Preview·표지 안내문 문장을 다듬어 쓴다.
- 기호(`symbol`)는 과목을 상징하는 **굵은 직사각형·원 위주의 단순한 블록**. 회로는 `circuit`, 그 외는 `blocks` 또는 `references/cover-design.md` 규칙대로 SVG 조각을 만든다.
- 책등 두께는 내지 쪽수로 계산된다. 실제 쪽수가 나오면 다시 돌린다.

## 9단계. 전달
PDF들(내지, 표지 펼침면, 앞·뒤·책등)을 보내고 짧게: 범위, TOPIC 목록, 검증한 답 개수, 쓴 기본값, 다음 단계. 마지막 한 줄: "원서·강의 자료를 바탕으로 만들었으니 개인 학습용으로만 쓰세요."
