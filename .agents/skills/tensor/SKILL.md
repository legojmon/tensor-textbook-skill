# TENSOR 교재 제작

이 파일에서 세 단계 위가 저장소 루트다. 루트의 `tensor/SKILL.md`를 읽고 그 지침과 참조 문서에 따라 작업한다. `<skill>`은 이 진입점이 아니라 루트의 `tensor/`를 가리킨다. 모든 명령은 같은 Python 환경에서 실행한다. 견본 조판 비교만 요청받으면 `python tensor/scripts/selfcheck.py`를 실행한다.

## Codex에서 검토받기

공통 지침의 1-B·2·9단계에서 검토 자료와 결과물을 현재 Codex 대화에 직접 전달한다. Google Docs·Drive에 결과물을 작성하거나 업로드하는 것은 사용자가 해당 목적지를 명시적으로 요청한 경우에만 한다. 입력으로 받은 Google 문서 링크는 자료의 출처로만 취급한다.

1. **제작 전 질문.** 강의록·원서와 앞선 답변에서 확인한 내용은 그대로 적용한다. 범위, 시험 형식, 누락된 자료의 처리처럼 답에 따라 원고가 달라지는 항목만 묻는다. 사용자가 맡긴 선택은 기본값을 적용하고 간단히 알린다.
2. **TOPIC 구성안.** 공통 지침 2단계의 표를 대화에 Markdown 표로 펼쳐 보여준다. 이어서 질문 카드로 다음 작업을 선택받는다. 장 전체를 의뢰한 경우의 예는 ‘이 구성으로 집필’, ‘구성 수정’, ‘한 TOPIC 시안 먼저’다. 이미 시안만 요청했다면 해당 TOPIC을 표시하고 그 범위에 맞춰 묻는다. 수정 의견은 제목·순서·병합 등을 반영한 표로 다시 보여준다. 사용자가 확정한 구성은 **TOPIC 최종안**으로 대화에 표시하고, 구성안만 의뢰했다면 여기서 마친다.
3. **TOPIC 조판 시안.** 선택된 TOPIC만 공통 지침 3~7단계로 제작한다. 실제로 생성하고 열어 확인한 **시안 PDF**를 TOPIC 번호·제목과 함께 대화에 첨부하거나 클릭 가능한 파일 링크로 전달한다. PDF 렌더링에 실패하면 공통 지침의 HTML 대체 절차를 따르고 파일 형식을 밝힌다. 시안만 의뢰했다면 전달로 마친다. 전체 제작 전에 시안을 검토하는 경우에는 파일을 먼저 보여준 뒤 ‘이 형식으로 계속’과 ‘시안 수정’ 중 선택받는다.
4. **최종 교재.** 승인된 범위를 제작·검수한 뒤 **최종 PDF**를 대화에 첨부하거나 링크한다. 시안과 구분되는 파일명을 쓰고 링크가 검수한 파일을 가리키는지 확인한다.

### 질문 카드 사용법

- 선택이 필요할 때는 현재 세션에 노출되어 호출 가능한 Codex 질문 도구(`request_user_input` 등)를 우선 호출한다. 검토할 표·파일과 선택에 필요한 설명은 호출 **전에 대화에** 보여준다.
- 한 번에 한 결정을 묻고, 함께 답할 수 있는 질문만 최대 3개까지 묶는다. 각 질문에는 서로 겹치지 않는 짧은 선택지 2~3개와 결과를 설명하는 한 문장을 둔다. 추천안은 첫 번째로 두고 도구 스키마의 추천 표기를 따른다. 직접 입력은 카드가 제공하는 칸을 쓴다.
- 도구를 쓸 수 없거나 호출에 실패하면 같은 질문을 현재 대화에서 번호 선택 또는 자유 답변으로 받는다. 채팅으로 이미 받은 답도 적용한다. 무응답은 승인으로 기록하지 않는다.

## 원고와 조판 (Codex 에서 반드시 지킨다)

- 원고는 `work/book.json` 에 글만 쓴다. 형식은 `tensor/references/manuscript-schema.md`, 견본은 `tensor/references/example-manuscript.json`. **HTML·CSS 를 직접 쓰거나 고치지 않는다.** `python tensor/scripts/build.py work/book.json` 이 장 표지·목차·Preview·강의 선정 문제·TOPIC 부품(EX, 원서적·시험적 해법, 말풍선, 3탭 개념 박스, CORE, 채점 포인트, 강의 VS 연습문제 표)·적용문제·연습문제·Review·빠른 정답을 고정 부품으로 조립한다.
- 전달 전 세 명령이 모두 깨끗해야 한다: `build.py` 오류 0 → `lint.py` 경고 0 (시안은 `--draft`) → `render.py --strict` 검수 0. 하나라도 남으면 JSON 을 고치고 다시 돌린다. `--lenient` 는 사용자가 허락한 경우에만 쓰고 전달 때 밝힌다.
- 문제 번호는 L(강의 선정 문제)·A(적용문제)·B(연습문제)와 TOPIC 안의 EX 뿐이다. 다른 글자를 만들지 않는다. 모든 문제의 답을 `answers` 에 넣고 검증한다.
- EX 와 문제마다 그림을 준비한다. 그림이 필요 없는 문제만 `nofig` 에 이유를 쓴다.
- 보조 교재가 있으면 `sources` 에 책마다 이름과 장 번호를 선언하고, 출처는 그 이름으로 시작한다. 빌더가 장 번호 불일치를 잡는다.
- 시안(한 TOPIC)은 `"scope": "draft"`, 승인된 구성안 전체를 `plan` 에 둔다. 장 전체는 `"scope": "chapter"` 로 `plan` 의 모든 TOPIC 을 쓴다.
